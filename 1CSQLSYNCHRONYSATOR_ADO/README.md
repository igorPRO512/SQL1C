# 1CSQLSYNCHRONYSATOR

Расширение 1С (встроенный язык — русский), которое выгружает справочники и документы в MS SQL Server.

## Состав

| Объект | Назначение |
|---|---|
| `CommonModules/Ext1_СинхронизацияSQL` | Настройки, очередь, выгрузка в SQL, фоновое задание |
| `InformationRegisters/Ext1_ОчередьСинхронизацииSQL` | Очередь изменённых объектов |
| `ScheduledJobs/Ext1_СинхронизацияSQL_ОбработкаОчереди` | Регламентное задание: обработка очереди, интервал задаётся в обработке |
| `Ext/ManagedApplicationModule.bsl` | `&После("ПриНачалеРаботыСистемы")`: синхронизация при запуске |
| `DataProcessors/Ext1_НастройкиСинхронизацииSQL` | Внешняя обработка: строка подключения, объекты, флажки, расписание |

## Установка

1. Выполните **Конфигурация → Загрузить конфигурацию из файлов** из полной папки `1CSQLSYNCHRONYSATOR` (в ней должны быть `Roles` и `Languages`).
2. Если расширение было создано с английским встроенным языком, пересоздайте его с русским: свойство `ScriptVariant` задаётся при создании.
3. **Создайте подписку на событие вручную** в конфигураторе: ветка **Общие → Подписки на события → Добавить**, имя `Ext1_СинхронизацияSQL_ПриЗаписи`, событие `ПриЗаписи`, обработчик `Ext1_СинхронизацияSQL.ПриЗаписиОбъекта`, источник: все справочники и документы, которые нужно синхронизировать. Подписка не выгружается в XML, потому что список источников зависит от основной конфигурации.
4. Отключите **безопасный режим** у расширения, иначе COM-подключение `ADODB` не работает.
5. Обновите конфигурацию базы данных.
6. Откройте обработку **Настройки синхронизации SQL**, укажите строку подключения, отметьте объекты, включите флажки и нажмите **Сохранить**.

## Режимы

- **Направление обмена.** При полной синхронизации данные читаются из SQL и применяются к объектам 1С по GUID; затем текущее состояние объектов записывается в существующие SQL-строки через `UPDATE` либо добавляется через `INSERT`. SQL `NULL` и пустые строковые значения не меняют соответствующий реквизит. При обновлении существующей SQL-строки пустое строковое значение из 1С также пропускается, чтобы не затирать текст. В очереди после записи объекта действует направление 1С → SQL.
- **Ошибки импорта.** Если чтение или запись хотя бы одного SQL-поля объекта завершается ошибкой, этот объект не выгружается обратно в SQL в рамках текущей полной синхронизации, чтобы не затереть исходные данные неполными значениями. Ошибка записывается в журнал регистрации.
- Пустые строки не синхронизируются поверх непустых значений: они пропускаются при импорте в 1С и при обновлении существующих строк SQL. Такая защита предотвращает дальнейшую потерю текста, но не восстанавливает значение, если оно уже пустое в обеих системах.
- Пустые и некорректные значения реквизитов типа `УникальныйИдентификатор` пропускаются с записью ошибки, не отменяя импорт остальных полей объекта.
- **Преобразование объектов.** Для каждого справочника и документа создаётся отдельная таблица: колонки реквизитов строятся по метаданным 1С, а значения восстанавливаются в типы 1С. Строки хранятся как Unicode (`NVARCHAR(MAX)`), читаются из ADO как значения полей и передаются в SQL Unicode-параметрами; числа — с точностью и масштабом реквизита в `DECIMAL`, даты — как `DATETIME2`, ссылки — как GUID с восстановлением вида и имени объекта, перечисления — по имени значения. Составные значения хранятся с префиксом типа. Для иерархических справочников переносятся родитель, группа/элемент и владелец, когда он предусмотрен метаданными; для справочников и документов переносится пометка удаления.
- **SQL-текстовые поля.** При импорте строковые колонки SQL приводятся к `NVARCHAR(4000)`, чтобы ODBC Driver 17 не возвращал `NVARCHAR(MAX)` как некорректную строку через ADO; исходный размер проверяется через `DATALENGTH`. Значения свыше 4000 символов не усекаются и вызывают ошибку импорта строки. При выгрузке длинных значений используется Unicode-параметр ADO `adLongVarWChar`. Отладочные сообщения экранируют управляющие символы, чтобы они не вызывали ошибку XDTO.
- **Запись документов.** После применения реквизитов документ записывается в режиме `РежимЗаписиДокумента.Проведение`, в том числе при обновлении существующего документа. На сервере запись выполняется непосредственно через объект документа; обновлять форму перед записью не требуется. Проведение может завершиться ошибкой, если данные не проходят проверки конфигурации.
- **Обновление данных в сеансе.** После полной синхронизации кэш повторно используемых значений сбрасывается на сервере и клиенте, чтобы актуальные данные были доступны без перезапуска 1С. Уже открытые формы сохраняют собственное отображаемое состояние; закройте и откройте такую форму заново, чтобы перечитать объект.
- **Отладка.** В обработке установите флажок «Подробная отладка синхронизации (Сообщить)» и нажмите «Сохранить» или «Запустить». Включённый режим выводит через `Сообщить()` этапы обмена, таблицы и типы колонок, GUID объектов, результаты преобразования реквизитов, действия INSERT/UPDATE и ошибки. Строковые значения ограничиваются 160 символами; двоичные значения не выводятся. Отладку следует выключать после диагностики: сообщения могут содержать значения реквизитов.
- **Дата изменения в SQL.** В таблицах справочников и документов создаётся служебный столбец `ДатаИзменения` типа `DATETIME2`. Он заполняется текущим временем при вставке и обновлении объекта; старые NULL-значения заполняются при подготовке схемы. Если у объекта 1С есть реквизит с таким именем, он зарезервирован для системного времени.
- **После записи объекта.** Флажок «Синхронизировать после записи объектов». Объект ставится в очередь в той же транзакции. Очередь обрабатывает регламентное задание, поэтому изменения попадают в SQL в пределах интервала.
- **По расписанию.** Флажок «Использовать регламентное задание» и интервал в минутах. Кнопка **Сохранить** применяет расписание.
- **При запуске системы.** Флажок «Синхронизировать при запуске системы».
- **Вручную.** Кнопка **Запустить полную синхронизацию**.

## Ограничения

- Удаление объектов не отслеживается.
- Табличные части не переносятся.
- Если номер импортируемого документа уже занят в пределах периода нумерации, документ сохраняется с автоматически назначенным номером; конфликт записывается в журнал, затем новый номер выгружается в SQL.
- Поддержка отдельных сложных и составных типов зависит от метаданных конфигурации; значения, которые нельзя однозначно восстановить, пропускаются с записью ошибки в журнал.
- Новые реквизиты автоматически добавляются в существующие SQL-таблицы. Изменение типа существующего реквизита автоматически не мигрирует тип столбца — для этого требуется миграция схемы SQL.
- Строка подключения хранится открытым текстом. Для продуктива используйте `Trusted_Connection=yes`.
- SQL-запросы собираются конкатенацией строк, значения экранируются только одинарными кавычками.

Ошибки пишутся в журнал регистрации с именем `SQLSync`.
