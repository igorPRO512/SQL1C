# 1CSQLSYNCHRONYSATOR

Расширение 1С (встроенный язык - русский), которое выгружает справочники и документы в MS SQL Server.
Работа с SQL идёт через коннектор OPI MSSQL (внешняя компонента `OPI_MSSQL`), модули коннектора
находятся в расширении под префиксом `Ext1_OPI_*`.

## Состав

| Объект | Назначение |
|---|---|
| `CommonModules/Ext1_СинхронизацияSQL` | Настройки, очередь, выгрузка в SQL, фоновое задание |
| `CommonModules/Ext1_OPI_MSSQL` | Коннектор MSSQL (перенесён из OPI, см. лицензию ниже) |
| `CommonModules/Ext1_OPI_*` | Вспомогательные модули OPI, которые нужны коннектору |
| `InformationRegisters/Ext1_ОчередьСинхронизацииSQL` | Очередь изменённых объектов |
| `ScheduledJobs/Ext1_СинхронизацияSQL_ОбработкаОчереди` | Регламентное задание: обработка очереди, интервал задаётся в обработке |
| `Ext/ManagedApplicationModule.bsl` | `&После("ПриНачалеРаботыСистемы")`: синхронизация при запуске |
| `DataProcessors/Ext1_НастройкиСинхронизацииSQL` | Внешняя обработка: строка подключения, объекты, флажки, расписание |

## Установка

### 1. Внешняя компонента OPI_MSSQL

Без компоненты коннектор не работает. Компонента должна называться именно `OPI_MSSQL`:
модули ищут `AddIn.OPI_MSSQL.Main`.

1. Скачайте компоненту для вашей платформы из релизов OpenIntegrations:
   https://github.com/Bayselonarrend/OpenIntegrations/releases/latest
   Версия должна соответствовать версии модулей OPI (в `Ext1_OPI_Инструменты` указана версия `2.3.0`).
2. **Windows.** Распакуйте архив компоненты в каталог, например `C:\OPI\addins\OPI_MSSQL\`.
   Подключите её как внешнюю компоненту через конфигуратор: добавьте в расширение общий макет
   с именем `OPI_MSSQL` и загрузите в него zip-архив компоненты.
3. **Linux.** Распакуйте компоненту в каталог `addins` сервера 1С, например
   `/opt/1cv8/x86_64/<версия>/addins/`. Требуются GLIBC >= 2.18 и OpenSSL 3.x.
   Проверка зависимостей: `ldd OPI_MSSQL.so` не должен показывать missing libraries.
4. Отключите безопасный режим для расширения (COM и внешние компоненты в нём не работают).
5. Перезапустите сервер 1С.

Если при подключении появляется текст `Не удалось инициализировать внешнюю компоненту`,
проверьте архитектуру, зависимости и наличие макета `OPI_MSSQL`.

### 2. Конфигурация расширения

1. Выполните **Конфигурация → Загрузить конфигурацию из файлов** из полной папки `1CSQLSYNCHRONYSATOR`
   (в ней должны быть `Roles` и `Languages`).
2. Если расширение было создано с английским встроенным языком, пересоздайте его с русским: свойство `ScriptVariant` задаётся при создании.
3. **Создайте подписку на событие вручную** в конфигураторе: ветка **Общие → Подписки на события → Добавить**,
   имя `Ext1_СинхронизацияSQL_ПриЗаписи`, событие `ПриЗаписи`, обработчик `Ext1_СинхронизацияSQL.ПриЗаписиОбъекта`,
   источник: все справочники и документы, которые нужно синхронизировать.
   Подписка не выгружается в XML, потому что список источников зависит от основной конфигурации.
4. Обновите конфигурацию базы данных.
5. Откройте обработку **Настройки синхронизации SQL**, укажите строку подключения, отметьте объекты,
   включите флажки и нажмите **Сохранить**.

### 3. Строка подключения

Строка подключения передаётся коннектору OPI в формате ADO, например:

    Server=HOST\SQLEXPRESS;Database=PCRETAIL;IntegratedSecurity=True;

    Server=HOST,1433;Database=PCRETAIL;User Id=sync;Password="secret";

Для шифрованного соединения с самоподписанным сертификатом используйте настройки TLS из OPI
(см. документацию: https://openintegrations.dev/docs/Instructions/MSSQL, раздел TLS).

## Режимы

- **После записи объекта.** Флажок «Синхронизировать после записи объектов». Объект ставится в очередь
  в той же транзакции. Очередь обрабатывает регламентное задание, поэтому изменения попадают в SQL в пределах интервала.
- **По расписанию.** Флажок «Использовать регламентное задание» и интервал в минутах. Кнопка **Сохранить** применяет расписание.
- **При запуске системы.** Флажок «Синхронизировать при запуске системы».
- **Вручную.** Кнопка **Запустить полную синхронизацию**.

## Ограничения

- Удаление объектов не отслеживается.
- Табличные части не переносятся.
- Изменение реквизитов меняет состав колонок таблицы SQL через `ГарантироватьТаблицу` коннектора OPI.
  Удалённые колонки удаляются вместе с данными. Перед изменением состава объектов сделайте резервную копию.
- Полная выгрузка очищает каждую таблицу и вставляет строки заново. Транзакция действует в пределах одной таблицы,
  поэтому при сбое в середине выгрузки часть таблиц может оказаться обновлённой, а часть - нет.
- Строка подключения хранится открытым текстом. Для продуктива используйте `IntegratedSecurity=True`.
- Чтение из SQL обратно в 1С (`ОбработатьДанныеИзSQL`) пока не реализовано.
